# Domain documentation

## Before exploring the domain

Read GLOSSARY.md at the repository root and relevant decisions
in docs/adr/.

If GLOSSARY-MAP.md exists, follow its links to relevant glossaries
and context-specific decisions.

If these documents are absent, proceed silently.
Create them through domain-modeling when terms or decisions
are resolved.

## Layout

Use a single-context layout:
- GLOSSARY.md for domain vocabulary.
- docs/adr/ for architecture decision records.

## Vocabulary and decisions

Use glossary terms consistently in code, tests and issues.
Identify terminology gaps for domain-modeling.
Explicitly flag proposals that conflict with existing decisions.
